# 安全监控系统 · 项目说明书

**系统名称**：多源异构安全监控与告警系统（security-monitor）  
**文档版本**：1.0  
**适用对象**：实施人员、运维人员、二次开发人员  

更细的 Windows 安装步骤见：[Windows部署指南-小白版.md](./Windows部署指南-小白版.md)

---

## 1. 项目概述

本系统用于集中监控多台服务器与网络设备的安全相关事件，并在检测到登录/退出、高危操作等行为时，通过 **飞书机器人** 推送告警卡片。

核心能力：

- 服务器侧安全事件采集（**Agent 主动上报** 或 **SSH 服务端拉取**）
- 登录/退出会话告警（按账号状态机：登录推一次、保持登录不刷屏、退出再推）
- 高危操作告警（创建用户、特权组变更、装服务、清日志等）
- 网络设备健康检查（SNMP）；Syslog 接收尚未实现
- Web 管理台：服务器、告警历史、飞书模板、用户与系统设置

## 3. 系统架构

```
┌──────────────────────────────────────────────────────────┐
│                     管理端（Docker）                       │
│  ┌─────────┐   ┌──────────┐   ┌────────┐   ┌─────────┐  │
│  │  Web    │──▶│   App    │──▶│Postgres│   │  Redis  │  │
│  │ :3000   │   │  :8000   │   │ :5432  │   │  :6379  │  │
│  └─────────┘   └────┬─────┘   └────────┘   └─────────┘  │
│                     │                                    │
│              ┌──────┴──────┐                             │
│              │ 规则引擎     │──▶ 飞书 Webhook             │
│              │ 飞书通知器   │                             │
│              └─────────────┘                             │
└──────────────────────▲───────────────────────────────────┘
                       │
        ┌──────────────┼────────────────┐
        │              │                │
   Agent 上报      SSH 拉取         SNMP/Syslog
   (推荐)         (备选)            (网络设备)
        │              │
   Windows/Linux   Windows/Linux
   被监控主机       被监控主机
```

### 数据流（推荐：Agent）

1. 目标机 Agent 本地采集登录/高危事件  
2. HTTPS/HTTP POST 到管理端 `/api/v1/agent/events`（Header：`X-Agent-Token`）  
3. 规则引擎去重、入库  
4. 飞书推送（可配置模板）  

### 数据流（备选：SSH）

1. 管理端定时或手动 SSH 登录目标机  
2. 执行采集脚本，取回结构化事件  
3. 同样进入规则引擎 → 飞书  

飞书卡片中的 **数据来源** 字段会标明是「Agent 客户端上报」还是「SSH 服务端拉取」。

## 5. 功能模块说明

### 5.1 服务器管理

- 增删改服务器档案  
- 采集模式：`agent` / `ssh` / `both`  
- 下载预配置 Agent 安装包（Token、server_url 已写入）  
- 展示 **当前通道**（此刻实际推送还是拉取）  
- SSH 测试 / SSH 拉取（仅 SSH 或混合模式显示）  
- SSH 主机密钥首次信任：首次连接记录服务器公钥，之后不一致即拒绝连接（防中间人）；服务器重装系统后在列表中点「重置密钥」  

### 5.2 Agent 客户端

**Windows 监控项（示例）：**

| 事件 | 含义 |
|------|------|
| 4624 / 4634 / 4647 | 登录 / 退出（过滤交互与 RDP 等类型） |
| 4720 | 创建用户 |
| 4732 | 特权组成员变更（普通 Users 组不告警） |
| 4697 / 4698 | 安装服务 / 计划任务 |
| 1102 | 清空安全日志 |

**Linux 监控项（示例）：** SSH 登录会话、sudo、useradd/userdel 等。

### 5.3 飞书告警

- 自定义标题/正文模板（Markdown + `{{变量}}`）  
- 告警级别过滤、防抖秒数  
- 登录/退出、高危、网络设备开关  

### 5.4 告警历史 / 用户 / 系统设置

- 告警列表与状态  
- 多用户与角色（JWT 登录）：管理员 / 运维 / 只读；只读用户看不到 Agent、采集器 Token  
- 登录防爆破：同一账号连续失败 5 次锁定 15 分钟，管理员可在用户管理中「解锁」（重置密码也会解锁）  
- 保留天数、采集间隔等系统参数  

### 5.5 操作审计（仅管理员）

- 自动记录所有写操作：登录（含失败原因）、增删改服务器 / 设备 / 站点 / 用户、重置密码 / Token / 主机密钥、修改设置、处理告警等  
- 记录操作人、动作、对象名称、结果、来源 IP、时间；**不记录请求内容**，密码等敏感信息不会进入审计表  
- 「操作审计」页面可按操作人、动作、结果、日期筛选；默认保留 180 天  
- 来源 IP 为直连地址；经 nginx 访问时显示为 nginx 容器地址，真实 IP 见 X-Forwarded-For（可被伪造，仅供参考）  

### 5.6 网络设备（可选）

- SNMP 巡检  
- Syslog 接收：**尚未实现**（端口不再对外开放，界面已隐藏开关）

## 7. 配置说明

### 7.1 `.env`

| 变量 | 说明 |
|------|------|
| DB_NAME / DB_USER / DB_PASSWORD | PostgreSQL |
| FEISHU_WEBHOOK_URL | 飞书机器人地址（也可在网页配置） |
| FEISHU_SECRET | 飞书签名密钥（可选） |
| LOG_LEVEL | 日志级别 |
| LOGIN_MAX_FAILURES / LOGIN_LOCK_MINUTES | 连续登录失败几次锁定、锁定分钟数（默认 5 / 15） |
| AUDIT_RETENTION_DAYS | 操作审计保留天数（默认 180） |

### 7.2 采集模式如何选择

| 模式 | 适用场景 |
|------|----------|
| 仅 Agent | 推荐；实时、少刷屏；目标机需能访问管理端 8000 |
| 仅 SSH | 装不了 Agent；管理端能 SSH 到目标机 |
| 混合 | Agent 优先；Agent 离线时退回 SSH |

## 8. 主要 API（摘要）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/auth/login` | 登录 |
| GET | `/api/v1/servers` | 服务器列表 |
| GET | `/api/v1/servers/{id}/agent-package` | 下载 Agent 安装包 |
| POST | `/api/v1/agent/heartbeat` | Agent 心跳（Token） |
| POST | `/api/v1/agent/events` | Agent 上报事件（Token） |
| GET/PUT | `/api/v1/feishu/config` | 飞书配置 |
| POST | `/api/v1/users/{id}/unlock` | 解除登录锁定（管理员） |
| POST | `/api/v1/servers/{id}/reset-host-key` | 重置 SSH 主机密钥（运维及以上） |
| GET | `/api/v1/audit-logs` | 操作审计（管理员，支持 username / action / success / start / end 筛选） |

Agent 鉴权请求头：`X-Agent-Token: <服务器绑定的 token>`

Agent / 采集器 Token 在数据库中加密存储（`CREDENTIAL_KEY`），鉴权按 SHA-256 摘要查找；仅泄露数据库无法冒充 Agent。升级时历史明文 Token 自动迁移，已安装的 Agent 无需改动。若更换了 `CREDENTIAL_KEY`，需在管理端重置 Token 并重新安装。

## 9. 运维建议

1. **备份**：定期备份 PostgreSQL 卷或逻辑导出。  
2. **日志**：`docker compose logs -f app`。  
3. **升级**：更新代码后执行 `docker compose up -d --build`；目标机重新下载 Agent 安装包覆盖。  
4. **安全**：公网部署时仅开放 3000/8000；数据库密码须更换，`JWT_SECRET` / `CREDENTIAL_KEY` 必须设置为随机值（后者设置后勿更换）。  
5. **穿透**：内网管理端 + 公网 Agent 时，保持穿透进程常驻，域名变更后需重装/改 Agent 配置。

## 10. 已知设计说明

- Web 映射端口为 **3000**（避免与本机 80 冲突）；可按环境改为 `80:80`。  
- Agent 在线判定：最近约 5 分钟内有 `agent_last_seen`。  
- 创建用户会伴随加入 Users 组的系统事件；系统会抑制普通组变更，只保留创建用户及特权组变更告警。  
- 同一分钟内同类「创建用户」做了去重，避免旧/新 Agent 双开导致双推。
